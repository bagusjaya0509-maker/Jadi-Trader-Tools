ATURAN FIRESTORE — PRATINJAU 24 JAM + AKSES LEWAT KODE
===========================================================================

INI BAGIAN YANG PALING PENTING DARI SELURUH FITUR AKSES.

Penguncian di halaman web cuma tampilan — siapa pun bisa membukanya lewat
view-source. Aturan di bawah ini jalan di server Google dan TIDAK BISA
disentuh dari peramban.

Buka: Firebase Console → Firestore Database → tab "Rules" → Publish.

---------------------------------------------------------------------------
APA YANG BERUBAH (17 Agu 2026) DAN KENAPA ITU WAJIB
---------------------------------------------------------------------------

Jendela otomatis dipendekkan dari 30 HARI jadi 24 JAM, mengikuti mode
pratinjau di web.

Ini BUKAN sekadar penyelarasan angka. Selama aturan di bawah masih menulis
30 hari sementara layar mengunci sesudah sehari, server tetap MENGIZINKAN
tulis selama 29 hari sesudahnya — siapa pun yang mau cukup memanggil
Firestore langsung dari console peramban dan gerbangnya tidak ada artinya.
Layar yang mengunci tanpa aturan yang ikut mengunci adalah gembok yang
digantung di pintu tanpa dikaitkan.

---------------------------------------------------------------------------
SALIN SELURUHNYA (ini aturan LENGKAP, sudah termasuk blok public/ yang lama)
---------------------------------------------------------------------------

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // ---- Status akses ----------------------------------------------------
    // Dokumen ini yang menentukan siapa boleh memakai fitur berbayar.
    //
    // create : boleh SEKALI oleh pemiliknya sendiri, dan field "mulai" WAJIB
    //          sama dengan waktu server (request.time). Halaman mengirim
    //          serverTimestamp(), jadi jam di HP tidak bisa dipakai memundurkan
    //          tanggal mulai. Field lain tidak boleh ikut ditulis.
    // update : DITOLAK untuk pengguna biasa -> pratinjau tidak bisa di-reset
    //          dan bayarSampai tidak bisa dipalsukan sendiri.
    // delete : DITOLAK -> hapus dokumen lalu buat baru juga tidak bisa.
    //
    // Ketiganya bersama-sama yang membuat "pratinjau sekali per akun" benar:
    // tanpa penolakan update DAN delete, 24 jam itu bisa diulang tanpa batas.
    match /langganan/{uid} {
      allow read: if request.auth != null
                  && (request.auth.uid == uid || request.auth.uid == 'EOrakx0QnSVgsi6BECSOXvUM9kG3');

      allow create: if request.auth != null
                    && request.auth.uid == uid
                    && request.resource.data.keys().hasOnly(['mulai'])
                    && request.resource.data.mulai == request.time;

      // SATU-SATUNYA update yang boleh dilakukan pengguna biasa: memasang
      // field "pratinjau" SEKALI, dengan waktu server.
      //
      // Empat syarat, dan keempatnya perlu:
      //  - fieldnya BELUM ada  -> pratinjau tidak bisa diulang
      //  - nilainya request.time -> jam perangkat tidak bisa dipakai
      //  - hanya "pratinjau" yang berubah -> bayarSampai tidak bisa
      //    ikut disisipkan dalam permintaan yang sama
      //  - "mulai" tidak berubah -> catatan kapan akun ini datang aman
      //
      // Hilangkan salah satunya dan 24 jam itu berhenti berarti apa-apa.
      allow update: if request.auth != null
                    && request.auth.uid == uid
                    && !('pratinjau' in resource.data)
                    && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['pratinjau'])
                    && request.resource.data.pratinjau == request.time;

      allow update, delete: if request.auth != null
                            && request.auth.uid == 'EOrakx0QnSVgsi6BECSOXvUM9kG3';
    }

    // ---- Data pribadi tiap pengguna --------------------------------------
    // BACA selalu boleh untuk pemiliknya — orang tidak boleh kehilangan akses
    // ke riwayat tradingnya sendiri hanya karena pratinjaunya habis.
    // TULIS butuh akses aktif: itulah yang membuat jurnal jadi baca-saja
    // sesudah 24 jam.
    match /users/{uid} {
      allow read: if request.auth != null && request.auth.uid == uid;
      allow write: if request.auth != null
                   && request.auth.uid == uid
                   && aksesAktif(uid);
    }

    // ---- Jurnal contoh untuk pengunjung (blok lama, jangan dihapus) -------
    match /public/{docId} {
      allow read: if true;
      allow write: if request.auth != null
                   && request.auth.uid == 'EOrakx0QnSVgsi6BECSOXvUM9kG3';
    }

    // ---- Catatan keanggotaan lama (blok lama, jangan dihapus) -------------
    match /members/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }

    // ---- Layout default yang diwarisi pengguna baru -----------------------
    // DIBIARKAN PERSIS seperti aturanmu yang sudah jalan: syarat tulisnya pakai
    // EMAIL, bukan uid. Jangan diganti ke uid tanpa alasan - yang sekarang
    // sudah terbukti bekerja, dan mengubahnya cuma menambah risiko.
    match /config/{doc} {
      allow read: if request.auth != null;
      allow write: if request.auth != null
                   && request.auth.token.email == 'bagusjaya0509@gmail.com';
    }

    // ---- Penolong --------------------------------------------------------
    // Dokumen langganan selalu berupa map: kalau belum ada, hasilnya map
    // KOSONG, bukan null. Bentuk ini dipilih supaya tidak ada satu pun jalur
    // yang bisa membaca field dari dokumen yang tidak ada.
    function langgananData(uid) {
      return exists(/databases/$(database)/documents/langganan/$(uid))
        ? get(/databases/$(database)/documents/langganan/$(uid)).data
        : {};
    }

    function aksesAktif(uid) {
      return uid == 'EOrakx0QnSVgsi6BECSOXvUM9kG3'
        // masih di dalam PRATINJAU 24 jam.
        //
        // Dihitung dari "pratinjau", BUKAN dari "mulai". Bedanya menentukan
        // segalanya: "mulai" ditulis pada login pertama siapa pun, jadi
        // memakainya berarti setiap orang yang login otomatis dapat 24 jam
        // dan kuota event 30 hari di /akses jadi tidak ada gunanya.
        // "pratinjau" hanya ada kalau orangnya menekan tombol Preview.
        || (
          'pratinjau' in langgananData(uid)
          && langgananData(uid).pratinjau + duration.value(24, 'h') > request.time
        )
        // atau aksesnya sudah dibuka lewat kode / persetujuan
        || (
          'bayarSampai' in langgananData(uid)
          && langgananData(uid).bayarSampai > request.time
        );
    }
  }
}

---------------------------------------------------------------------------
CARA MEMBUKA AKSES SESUDAH ORANG MEMBAYAR / DISETUJUI
---------------------------------------------------------------------------

Jalur normalnya lewat halaman Maintenance → Permintaan Akses (backend yang
menulis bayarSampai). Manual lewat Firebase Console kalau perlu:

  1. Firestore Database → koleksi "langganan" → cari dokumen dengan uid orang
     itu. (Kalau tidak tahu uid-nya: minta emailnya, lalu cocokkan lewat
     Authentication → Users.)
  2. Tambah/ubah field  bayarSampai  bertipe timestamp.
  3. Selesai. Halaman orang itu berubah TANPA muat ulang — web memasang
     pemantau hidup di dokumen ini.

---------------------------------------------------------------------------
CATATAN YANG PERLU KAMU SADARI
---------------------------------------------------------------------------

• Akun yang dokumen langganannya SUDAH ADA sebelum perubahan ini otomatis
  dianggap habis pratinjaunya — `mulai`-nya sudah lewat 24 jam. Itu memang
  yang diinginkan: mereka sudah pernah melihat isinya. Yang punya
  bayarSampai aktif tidak terpengaruh sama sekali.

• Tiap kali pengguna MENULIS ke users/{uid}, aturan ini membaca dokumen
  langganan/{uid}. Satu pembacaan itu ikut terhitung kuota Firestore.

• Orang bisa membuat akun Google baru untuk mendapat 24 jam lagi. Ini tidak
  bisa ditutup sepenuhnya di sistem mana pun yang memakai login gratis —
  tapi imbalannya sekarang sehari, bukan sebulan, dan itu jauh lebih kecil
  daripada ongkos membuat akun baru berulang kali.
